# Тестовое задание: палиндром на PHP

Проверка, является ли переданный текст палиндромом (читается слева направо и справа налево одинаково), плюс HTTP-эндпоинт и набор тест-кейсов.

[![CI](https://github.com/eastlemon/neimark-test-task/actions/workflows/ci.yml/badge.svg)](https://github.com/eastlemon/neimark-test-task/actions/workflows/ci.yml)

Решение намеренно сделано **без фреймворка**: чистый PHP 8.1+ с composer-автозагрузкой. Так проще видно, что делает сам код, а обвязка (Symfony/Laravel-контроллер) добавляется поверх без изменений доменной логики.

## Как это устроено

- **Два режима проверки:**
  - `normalized` (по умолчанию) — регистр, пробелы и знаки препинания игнорируются: «А роза упала на лапу Азора» — палиндром;
  - `strict` — посимвольное сравнение строки «как есть».
- **UTF-8, а не байты.** Классический `strrev()` переворачивает байты и на кириллице даёт невалидную последовательность, поэтому строка режется по символам через `mb_str_split()` и сравнивается **двумя указателями** (с начала и с конца) — O(n) с ранним выходом при первом несовпадении.
- **Нормализация.** `mb_strtolower()` для регистронезависимости; регулярное выражение `[^\p{L}\p{N}]` оставляет буквы и цифры любых алфавитов (Unicode-категории L* и N*), выбрасывая пунктуацию и символы.
- **Валидация входа.** Невалидный UTF-8 → `InvalidArgumentException` (в HTTP-слое — 400); слишком длинный текст → 413; не-POST → 405; отсутствующее поле `text` → 400.
- **Пустая строка** — тривиальный палиндром (возвращается `true`; в реальном ТЗ это вопрос к аналитику — можно валидировать и отдавать 422).

## Запуск (podman, docker — аналогично)

Требования: PHP 8.1+, расширение `ext-mbstring` (включено по умолчанию).

```bash
# установка зависимостей
podman run --rm -v "$PWD":/app -w /app docker.io/library/composer:2 install

# юнит-тесты
podman run --rm -v "$PWD":/app -w /app docker.io/library/php:8.2-cli vendor/bin/phpunit --testdox

# локальный сервер
podman run --rm -p 8080:8080 -v "$PWD":/app -w /app \
    docker.io/library/php:8.2-cli php -S 0.0.0.0:8080 -t public
```

## Примеры запросов

```bash
# палиндром с пробелами и заглавными
curl -s -X POST localhost:8080 \
     -H 'Content-Type: application/json' \
     -d '{"text": "А роза упала на лапу Азора"}'
# {"text":"А роза упала на лапу Азора","isPalindrome":true,"mode":"normalized"}

# strict-режим: регистр и пунктуация учитываются
curl -s -X POST localhost:8080 \
     -H 'Content-Type: application/json' \
     -d '{"text": "Abba", "strict": true}'
# {"text":"Abba","isPalindrome":false,"mode":"strict"}

# не палиндром
curl -s -X POST localhost:8080 -H 'Content-Type: application/json' -d '{"text": "привет"}'
# {"text":"привет","isPalindrome":false,"mode":"normalized"}
```

## Тест-кейсы

| № | Входные данные | Обычный режим | Strict | Что проверяем |
| --- | --- | --- | --- | --- |
| 1 | `казак` | true | true | базовый кейс, кириллица |
| 2 | `Казак` | true | false | регистр игнорируется только в обычном режиме |
| 3 | `А роза упала на лапу Азора` | true | false | пробелы, длинная фраза |
| 4 | `Лёша на полке клопа нашёл` | true | false | буква «ё» с обеих сторон |
| 5 | `Madam, I'm Adam` | true | false | латиница, пунктуация, апостроф |
| 6 | `Abba` | true | false | чётная длина, регистр |
| 7 | `12321` | true | true | цифры тоже считаются |
| 8 | `1а2а1` | true | true | буквы и цифры вперемешку |
| 9 | `а😀а` | true | true | многобайтный UTF-8, эмодзи |
| 10 | `привет` | false | false | негативный кейс |
| 11 | `12345` | false | false | негативный кейс с цифрами |
| 12 | `` (пустая строка) | true | true | граничный случай |
| 13 | `Ж` (один символ) | true | true | граничный случай |
| 14 | байты `"\xB1\x31"` | исключение | исключение | невалидный UTF-8 → в HTTP-слое 400 |

## Известные ограничения и что бы я улучшил

- **Grapheme-кластеры.** Эмодзи из нескольких кодовых точек (например, 👍🏽 = палец + модификатор тона кожи) разбиваются на отдельные кодовые точки, и strict-режим скажет «не палиндром», хотя визуально это палиндром. Лечится разбором через `\X` в PCRE (extended grapheme clusters).
- **Нормализация NFC.** Буквы с диакритикой, набранные как базовый символ + combining-знак, сравнивались бы неверно; нужен `Normalizer::normalize()` из ext-intl.
- **Договорённость «ё/е» и цифры.** Решение о том, что «ё» не превращается в «е», а цифры участвуют в проверке, — вопрос к аналитику, зафиксирован в коде и тестах.
- **Прод-обвязка.** В реальном проекте эндпоинт — это контроллер фреймворка с DTO и валидатором, плюс rate-limiting и структурированное логирование.
